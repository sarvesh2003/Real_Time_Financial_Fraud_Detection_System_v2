# PROJECT_CHEAT_SHEET.md
### Fault-Injection Testbed & Evaluation Framework for LLM Diagnostic Agents

> **Use this for a 5–10 minute review.** Source-only rewrite. Where the original documentation and later code audit disagree, use the audit-corrected fact.

## 1. 60-second project pitch

I built a **fault-injection testbed and evaluation framework for LLM diagnostic agents**.

The harness injects controlled, reversible faults into an inherited Docker Compose fraud-detection pipeline, so the true root cause is known **by construction**. A deliberately small **LangGraph** agent investigates with six **read-only MCP tools**, a 15-call budget, and a code-enforced confidence gate.

The evaluation measures not just correctness, but the failure I care about most: **false confidence** — being confidently wrong. It uses mechanical rubric grading, Wilson 95% confidence intervals, a cost matrix, and a separate validity gate.

The most important result was negative: the validity checks showed that much of the original dataset was not trustworthy. **Six faults were fully answerable from free context**, and a **null model** that made zero tool calls originally scored **2/6 = 33%**. On the residual n=14 subset, the agent got **0 correct** and abstained in **9/14 = 64%** of runs — but even that subset is still partly contaminated and shrinks to **n=4** under the stricter leakage rule. The system therefore does **not** demonstrate strong diagnostic capability; the stronger contribution is the evaluation machinery that detected why the earlier numbers were invalid.

## 2. Architecture flow

```text
run_fault_eval.sh
  → rotate changelog
  → inject one reversible fault
  → Docker Compose fraud stack changes
  → agent/run.py starts MCP server + Chroma + LangGraph
  → baseline sweep (free)
  → investigate ↔ tool_call, max 15 model-chosen calls
  → conclude with structured JSON
  → code may downgrade confidence
  → write trace.jsonl + result.json
  → restore fault
  → grade.py → results.csv / review queue
  → aggregate.py → per-group metrics
  → contamination + validity checks → fail on invalid experiment
```

**Target stack:** `go-server → Kafka/ZooKeeper → go-enricher → redis1/2/3`, plus Python load generator, Prometheus, and exporters.

**Important ownership boundary:** the fraud pipeline was inherited. New project work is mainly `agent/`, `corpus/`, `eval/`, `fault-injection/`, `mcp-server/`, `prometheus/`, plus `metrics.go` changes in the Go services.

## 3. Key components

| Component | What matters |
|---|---|
| **Fault injection** | 16 `inject/restore` scripts across Redis, Kafka, network, and config faults. **15 are gradable; only 7 were actually run.** Fault 5 is ungradable. |
| **LangGraph agent** | 4 nodes: `baseline → investigate ↔ tool_call → conclude`. Evidence log is the memory; each turn rebuilds a fresh two-message prompt from state. |
| **MCP / FastMCP** | 6 read-only tools over stdio: logs, PromQL metrics, metric names, container state, config, recent changes. |
| **Baseline sweep** | Before the model acts: container state, 24h change log, `up` metric over 1h, and config for every running service. Usually **15–16 evidence entries**, free of the 15-call budget. |
| **`config_diff`** | Synthetic peer comparison generated by the graph, not an MCP tool. It still counts as a distinct tool for corroboration. |
| **Retrieval / Chroma** | 5 past cases, 384-dim embeddings. `root_cause` excluded from embedding. Model sees only `fault_family/fault_name` labels for cases within distance ≤1.0. |
| **Grading** | Literal substring rubric over `summary + reasoning`: 2 correct, 1 partial, 0 wrong, −1 honest abstention. Human overrides are versioned. |
| **Validity** | `check_contamination.py` plus `eval/validity/`: 16 checks across 7 failure classes; exit 1 on violation. |

## 4. Most important design decisions

1. **Read-only tool surface.** The model never gets direct Docker access. Audit found only two `subprocess.run` sites, three HTTP GETs, and one file read; Redis access is hard-coded to `CONFIG GET` on five keys. **Limitation:** this is a manual code audit, not an automatically enforced security property.

2. **Free baseline sweep.** Every run starts with the same evidence, improving reproducibility. **Tradeoff:** it can solve faults before the model investigates and makes `calls_used` misleading.

3. **15-call model budget + charged duplicates.** Duplicate `(tool,args)` calls return `DUPLICATE` but still consume budget. **Tradeoff:** sweep calls are free, so a run can make roughly 30 real invocations while reporting `calls_used: 15`.

4. **Code-enforced confidence gate.** `confirmed → best_guess` if the model exhausts the 15-call budget or cites fewer than 2 distinct tools. Both self-reported and enforced confidence are stored. **Limitation:** it checks evidence breadth, not correctness; synthetic `config_diff` can satisfy it.

5. **Abstention is separate from wrong.** `inconclusive` with no claimed cause scores −1, not 0. The cost matrix prevents “always abstain” from trivially winning: confirmed-correct 0, best_guess-correct 1, inconclusive 3, best_guess-wrong 5, confirmed-wrong 10.

6. **Mechanical grader + human overrides.** Deterministic and auditable, but the measured disagreement rate is **7/38 ≈ 18%**. The review queue is only partially blind because it exposes matched rubric phrases.

7. **Never pool environment groups.** Metrics are reported per environment × retrieval mode with **Wilson 95% intervals** because sample sizes are tiny and model/host/fault set are confounded.

8. **Validity gate as a build failure.** The system explicitly asks whether an experiment is admissible before trusting its result. **Critical caveat:** the gate was added after the dataset was collected, so it diagnosed problems rather than preventing them.

## 5. Metrics / results — know the context

| Result | Context / limitation |
|---|---|
| **38 graded runs** | 7 faults across 6 environment labels. 56 result files exist; the grading glob selects 38. All 38 completed; zero `PARSE_FAILURE`. |
| Outcomes: **12 correct / 4 partial / 12 wrong / 10 abstained** | Dataset census only. **Do not call this an accuracy result.** |
| Enforced confidence: **17 confirmed / 11 best_guess / 10 inconclusive** | Confident-correct: 9. Confident-wrong: **8/38**. |
| Residual subset: **n=14 → 0 correct / 2 partial / 3 wrong / 9 abstained** | Faults 4/6/9/13, two hosted Qwen environments. But faults 6 and 9 are themselves leaked; stricter set is **n=4** (faults 4 and 13). |
| Abstention: **9/14 = 64%** | Indicates reluctance to guess on that subset, not diagnostic success. The subset caveat above applies. |
| Null model: **2/6 = 33% originally; 0/6 after corrections** | Six `local-qwen9b` runs were silently clamped to a 2,048-token context, first-turn `input_tokens=2050` vs **5,361–6,676** hosted; made **0 tool calls**. Establishes a floor, not an agent-vs-null comparison. |
| Grader disagreement: **7/38 ≈18%** | 5 wrongly credited, 2 wrongly zeroed. `score_overrides.csv` has 8 rows: 2 up, 5 down, 1 no-score-change. |
| Free-context leakage: **6 faults: 1, 3, 6, 9, 10, 15** | 4 are in the graded dataset. Contamination checker exits 1 with **9 failures, 60 warnings**. It proves answers were reachable, not that each run used the leak. |
| Retrieval distances: **0.558–0.999 across 214 events** | 1.0 cutoff trimmed results in **9/13** retrieval-on runs; to one entry in 8. Retrieval effect is **not claimable**. |
| Worked fault-2 run | Score 2; **10/15 calls**, 2 duplicates; **479.6 s**; 12 model calls; **106,314 input / 2,085 output tokens**; groundedness 1.0; baseline-citation fraction 0.5. Good mechanics, but much of the answer came from the free sweep and synthetic `config_diff`. |

## 6. Major limitations

- This is a **measurement instrument**, not a production incident-response system.
- One investigation, one environment, one fault per harness invocation. No general concurrency, queue, locking, auth, multi-tenancy, or durable graph state.
- Diagnosis only; **no remediation**.
- Only 7 of 16 built faults were run; fault 5 is ungradable; fault 15 is latent and produces no symptom alone.
- Model, host, and fault set are confounded. **No model ranking is valid.**
- Claude rows are **12 hand-transcribed chat-UI runs**, not equivalent harness runs.
- Retrieval ablation is invalid; no retrieval benefit/harm claim is supported.
- Mechanical substring grading mishandles negation, paraphrases, and ruled-out confounders.
- Context/tool documentation leaked answers into the prompt.
- The current validity gate postdates all graded runs.
- The current MCP server code at HEAD is not the exact version that produced the graded traces.
- `eval/summary.md` is **WITHDRAWN**. Do not cite its numbers.
- The LLM judge for faults 6/9/13 was implemented but **never completed**; its output files do not exist.

## 8. Things I must never overclaim

| Never say | Say instead |
|---|---|
| “The agent achieves X% accuracy.” | No pooled accuracy over the 38 rows is claimable. The residual n=14 subset had 0 correct, and even that subset is partly contaminated. |
| “I evaluated 16 faults.” | I built 16 scripts; 15 are gradable; **7 were actually run**. |
| “I benchmarked Qwen 9B vs 14B vs 32B vs Claude.” | Model size, host, scaffold, and fault sets are confounded; no model ranking is supported. |
| “Retrieval improved / hurt performance.” | The retrieval ablation is unclaimable. |
| “The confidence gate improves accuracy.” | It only changes confidence labels. It checks evidence breadth, not correctness. |
| “The agent fails safe.” | On the n=14 residual subset it abstained in 9/14 runs, but that subset itself has leakage and shrinks to n=4 under the stricter standard. |
| “The LLM judge validated the grader.” | It was implemented for faults 6/9/13 but never ran to completion. |
| “The validity gate certifies the dataset.” | It postdates the data and currently **invalidates** much of it. |
| “Claude was evaluated in the same harness.” | Those 12 rows were manually transcribed from Claude Desktop with a different scaffold and missing timing/token data. |
| “The change IDs are opaque.” | They are `sha256(family/fault)[:8]` over a 16-item known set and are reversible by enumeration. |
| “This is production-ready.” | It is a single-run experimental measurement system. |
| Anything from `eval/summary.md` | Do not cite it; it carries a **WITHDRAWN** banner. |
